// Auto-initialization for logged-in users
Future<void> _initializeNotifications() async {
  await NotificationService.initialize();
  
  // Update FCM token for this user
  final token = await NotificationService.getToken();
  if (token != null) {
    await _updateUserFCMToken(token);
  }
  
  // Listen for token refresh
  NotificationService.onTokenRefresh((newToken) {
    _updateUserFCMToken(newToken);
  });
}

// Store token in Firestore for admin targeting
Future<void> _updateUserFCMToken(String token) async {
  final user = FirebaseAuth.instance.currentUser;
  if (user != null) {
    await FirebaseFirestore.instance
        .collection('users')
        .doc(user.uid)
        .update({'fcmToken': token});
  }
}
```

## ========================================
## 💡 HOW THE SYSTEM WORKS
## ========================================

### 1. User Login Flow:
```
User Logs In → MainLayout.initState() → _initializeNotifications() 
→ NotificationService.initialize() → FCM Token Generated 
→ Token Stored in Firestore users/{uid}/fcmToken
```

### 2. Foreground Notification Flow:
```
Admin Action (e.g., mark attendance) → _sendAdminActionNotification() 
→ FCM message sent → FirebaseMessaging.onMessage listener triggered 
→ _showForegroundNotification() → flutter_local_notifications displays notification
```

### 3. Cloud Function Flow (Future Implementation):
```
Firestore fcm_messages collection → Cloud Function trigger 
→ Enhanced FCM payload construction → admin.messaging().send() 
→ Cross-platform delivery with foreground flags
```

### 4. Cross-Platform Handling:
```
Android: High-priority notification channel + vibration/sound
iOS: content-available flag + APNS priority 10 for foreground delivery
```

const {onRequest} = require("firebase-functions/v2/https");
const admin = require('firebase-admin');

admin.initializeApp();

exports.sendFCMNotification = onRequest(async (request, response) => {
  try {
    const { token, title, body, type } = request.body;
    
    const payload = {
      token: token,
      notification: { title: title, body: body },
      data: { type: type || 'notification' },
      android: {
        priority: 'high',
        notification: {
          channelId: 'high_importance_channel',
          priority: 'high',
          defaultSound: true,
        },
      },
      apns: {
        payload: {
          aps: {
            alert: { title: title, body: body },
            sound: 'default',
            'content-available': 1,
          },
        },
        headers: { 'apns-priority': '10' },
      },
    };

    const messageId = await admin.messaging().send(payload);
    response.send({ success: true, messageId: messageId });
  } catch (error) {
    response.status(500).send({ error: error.message });
  }
});
```

## ========================================
## 🔧 TROUBLESHOOTING GUIDE
## ========================================

### Common Issues and Solutions:

#### 1. Notifications Not Showing in Foreground
**Problem**: Notifications only appear when app is backgrounded
**Solution**: Ensure FirebaseMessaging.onMessage listener is properly set up and flutter_local_notifications is configured

#### 2. FCM Token Not Generated
**Problem**: getToken() returns null
**Solution**: Check permissions, ensure Firebase is initialized, verify google-services.json placement

#### 3. Cloud Functions Deployment Fails
**Problem**: ESLint errors or API permission issues
**Solution**: Disable ESLint in firebase.json or fix code formatting, wait for API permissions to propagate

#### 4. iOS Notifications Not Working in Foreground
**Problem**: iOS doesn't show foreground notifications
**Solution**: Ensure 'content-available': 1 flag is set in APNS payload

#### 5. Android Notification Channel Issues
**Problem**: Notifications not showing on newer Android versions
**Solution**: Properly create notification channels with appropriate importance levels

## ========================================
## 📊 PERFORMANCE CONSIDERATIONS
## ========================================

### Optimization Tips:

1. **Token Management**:
   - Cache tokens locally to avoid repeated Firebase calls
   - Update tokens only when changed (onTokenRefresh)
   - Clean up old tokens from Firestore

2. **Notification Batching**:
   - Avoid sending multiple notifications rapidly
   - Implement rate limiting for admin actions
   - Use topic subscriptions for broadcast messages

3. **Cloud Function Efficiency**:
   - Use 2nd gen functions for better performance
   - Implement proper error handling and retries
   - Monitor function execution time and costs

4. **Platform-Specific Optimizations**:
   - Use appropriate priority levels for each platform
   - Implement different strategies for Android/iOS
   - Consider battery optimization implications

## 🔐 SECURITY CONSIDERATIONS
## ========================================

### Security Best Practices:

1. **Token Security**:
   - Never expose FCM tokens in client logs
   - Implement token rotation policies
   - Validate tokens before sending notifications

2. **Authentication**:
   - Verify user authentication before storing tokens
   - Implement admin role verification for privileged operations
   - Use Firebase Security Rules for Firestore access

3. **Data Privacy**:
   - Minimize sensitive data in notification payloads
   - Implement proper data retention policies
   - Follow GDPR/privacy regulations for user data
